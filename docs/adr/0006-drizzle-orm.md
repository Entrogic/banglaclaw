# ADR-0006: Drizzle ORM for PostgreSQL Access

## Status

Accepted

## Context

v0.2 adds PostgreSQL persistence for sessions, messages, runs and tool calls (ADR-0004). We need typed queries, versioned migrations, and an access layer that stays behind the `SessionStore` / `RunStore` interfaces so storage remains replaceable.

## Decision

Use Drizzle ORM with the node-postgres (`pg`) driver in `packages/storage`:

- The schema is defined in TypeScript (`src/schema.ts`).
- SQL migrations are generated by drizzle-kit and committed (`packages/storage/drizzle/`).
- Migrations are applied at deploy/dev time through `banglaclaw db migrate`, never implicitly on startup.
- LangGraph checkpoints use `@langchain/langgraph-checkpoint-postgres` on the same connection pool, with its own tables.

## Consequences

Positive:
- Row types are inferred from the schema; queries are type-checked
- Plain, reviewable SQL migration files
- Lightweight runtime, with no query engine or code generation step at runtime

Trade-offs:
- drizzle-kit is an extra dev tool, and generated snapshots must be committed alongside migrations
- Checkpoint tables are managed by LangGraph's `setup()` rather than by Drizzle migrations
- Agent and session packages must not import Drizzle; only `packages/storage` does
